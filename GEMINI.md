# Gemini AI Instructions for this Repository

## The Context
You are assisting with the development of a web dashboard for a tennis tracking ecosystem. This frontend consumes data generated by a Wear OS application and served via a Go backend.

**Core Tech Stack:**
- Vue 3 (v3.5.25+) using Composition API & `<script setup>`
- Vite (v7.3.1)
- TypeScript
- Tailwind CSS (v3.4.19) + official plugins (forms, typography, container-queries)
- Vue Router
- Chart.js via `vue-chartjs`

## Your Directives

When writing code, proposing solutions, or refactoring in this repository, you MUST adhere to the following directives:

### 1. Read the Architecture
Before proposing any structural changes or creating new modules, you must assume the rules defined in:
- `architecture.md` (for folder structure and domain concepts)
- `laws_of_architecture.md` (for strict constraints on cross-feature communication and bundle size)

### 2. Feature-First Mindset
When asked to implement a new feature (e.g., "add a player profile page"):
- Do not dump everything into a global folder.
- Always determine which **Domain** the feature belongs to.
- Scaffold the internal folders (`components/`, `composables/`, `services/`, `types/`) inside that feature's directory.
- Always expose a public API via an `index.ts` file.

### 3. Coding Style
- **Vue:** Use `<script setup lang="ts">`. Avoid Options API entirely.
- **Styling:** Use utility classes from Tailwind CSS. Avoid custom `<style>` blocks unless absolutely necessary for complex animations or highly specific overrides.
- **TypeScript:** Be strict. Do not use `any`. Define clear interfaces for the data coming from the Go backend.
- **Charts:** When building statistics views, assume `vue-chartjs` and isolate the chart configuration within the feature's `components/` folder.

### 4. Zero-Bloat Policy
- Do not suggest installing heavy external libraries for state management (we use Pinia if needed, or simple composables), data mapping (write manual mappers), or generic UI components (build them with Tailwind).
- Always suggest lazy loading for route components.

### 5. AI Output Format
- Provide clean, copy-pasteable code blocks.
- If modifying an existing file, show only the relevant changes or clearly indicate where the new code fits, to avoid massive text walls.
- Briefly explain *why* a decision was made if it relates to the 4 Laws of Architecture.
